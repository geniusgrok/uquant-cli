# Uquant 盘后日报运行仓库

本仓库负责运行、刷新行情、维护连续观察状态、扫描13只标的、比较前一交易日并保存盘后日报。

私有策略仓库仅在运行时提供最新 main 的生产源码，只读获取；本仓库不向策略仓库写入报告、数据、日志、验证证据或其他生成物。

## 调度与运行

唯一盘后定时为周一至周五北京时间17:01（UTC cron `1 9 * * 1-5`）。每次先核验交易日历覆盖：北京时间15:30前（含非交易日）使用最近一个已完成交易日收盘数据生成该交易日的日报；15:30及之后的交易日使用当日数据。无法核验交易日历或目标日行情不完整时运行失败并保留审计记录。工作流支持手动启动及相关部署代码合并后的就绪检查；所有入口共享并发组与持久化交易日占用记录，手动启动也不能重复计算。

ChatGPT定时任务只获取当天已有运行，不重复触发扫描。

生产运行所需的访问配置仅保存在 GitHub Actions 的受保护设置中。报告提交仅使用本仓库工作流的短期权限，不设置额外的私有仓库写入通道，也不把访问配置传入生产进程。

根目录的`bootstrap.py`、`preflight.py`、`runner.py`和`verify_integrity.py`分别负责环境准备、启动检查、正式运行和集成验证；`uquant_cli/`保存行情、决策、报告及结果存储组件。运行时通过Python调用生产源码中的`ProductionEngine.decide`。不复制或修改生产策略、参数、风控和冻结数据。运行环境遵循源码`uv.lock`，使用Python 3.12.13与uv 0.11.33。长生产验证与扫描使用项目自带的Cloud Guard，但工作目录位于本仓库的运行空间。

## 报告和数据位置

所有正式生成物保存在本仓库的`uquant-daily-reports`分支：

- `latest_run.json`：最近一次执行状态、对应运行链接与记录路径；失败、休市或未收盘也会记录。
- `latest.json`：最后一次有效决策的结构化结果入口及完整性清单。
- `reports/YYYY-MM-DD.md`：与 trade-cli 一致的中文公开日报；`reports/YYYY-MM-DD/`保留结构化结果、决策和输入审计原件。
- 同日的`decision.json`：生产实际输出；目标或意图不代表实际成交。
- `state/account.json`：连续运行的非实盘观察账户，只使用系统默认模拟现金，不包含用户实盘输入。
- `inputs/`：实际计算行情、逐票原始展示报价、日期与质量审计；历史版本可按Git提交恢复。
- `claims/YYYY-MM-DD.json`：决策前写入的日期占用记录，确保只有一个运行者开始计算。
- `runs/RUN-ATTEMPT/`：执行事件、结果状态，以及失败时尚未发布的输入、决策原件和校验清单。

日报、结构化输出和非实盘观察数据按用户授权公开。私有策略源码、访问凭据、真实账户资料及包含源码内容的诊断信息不得公开。日志仅记录阶段、时间、退出码和异常类型，不将依赖安装输出或原始异常堆栈作为公开日志。没有额外的私有日志保存通道；临时运行器中未保全的原始调试输出不会被描述为已远端保存。

日报中每次出现标的代码，必须在同一处同时写出标的名称，例如“688498 源杰科技”。标题、表格、重点变化、昨日比较和正文均遵循此规则，不得只展示代码。

股票历史、指数历史和不复权展示报价均支持东财、新浪、腾讯备用通道。每个来源必须通过同一生产数据校验及目标交易日检查；一次完整来源调用最多25秒，失败后切换来源，并优先复用本轮已验证可用的来源。审计记录保存每项行情的实际来源、请求结果、日期、行数和成交额是否沿用生产估算口径。

股票保持前复权，指数保持原始指数口径，成交量统一为股。切换来源时获取整个所需历史，不拼接不同来源的复权序列。日报收盘价单独取不复权行情；备用源没有提供交易所涨跌幅时显示“未提供”，不在除权日用原始前收价错误推算。全部来源失败、目标日缺失或生产校验不通过时停止计算，不回退到旧数据。完整参考池、指数和预热历史仍须通过生产校验。

官方接口说明：

- [指数历史行情](https://akshare.akfamily.xyz/data/index/index.html#index-zh-a-hist)
- [数据工具](https://akshare.akfamily.xyz/data/tool/tool.html)

这是连续、不执行的观察账户：不假造用户资金、持仓或成交，不每日重置风险状态，不把订单意图写成已成交。没有实际订单不推断为持有或允许买入；不存在的字段写“未提供”。Risk Sentinel覆盖状态非READY时标为“部分结果”，不宣称风险资料完整。

昨日指前一交易日。旧结果须校验清单、观察身份、经济代码和配置；不存在可靠基线时标为“不可比较”，不补造历史。保留订单的signal_date，用于区分旧意图和新信号。

## 幂等、事务与恢复

输入校验通过后，先正常推送并回读当天日期占用记录，再调用一次生产引擎。未知或未完成的占用记录会阻止自动重算；数据、代码、配置变化及漏交易日仍遵循生产连续性校验，不能清空账户来修复。

报告、状态和输入通过一次Git提交及分支更新原子发布；每个文件均回读远端字节，并核验长度、SHA-256与Git blob OID。推送结果不确定时先读取远端状态，不盲目重推或强制覆盖。发布失败后的原始决策只保存在运行恢复区，不冒充最新有效报告。写入通道完全失败时明确说明临时原件风险，不误报已保存。恢复诊断前先读取日期占用、最新报告和运行记录。

## 验证

公共启动检查验证账号和读写权限隔离以及单一调度。运行层定向测试覆盖交易日历、字段缺失、13只标的完整性、状态连续性、同日去重、并发日期占用和远端Git字节回读。

`delivery-validation.yml`会在本仓库读取当前生产 main，执行连续两个历史夹具决策，再验证第三次同日调用不会进入引擎，并在重新读取已保存账户后核验一致性。该流程是生产集成测试，不是当日行情扫描；不会对外发布私有源码、夹具日报或向源码仓库写入验证结果。
